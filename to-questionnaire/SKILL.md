# 前往问卷

将未解决的利益相关者依赖性、业务规则未知性和外部域模糊性转化为高收益的结构化调查问卷，最大限度地减少异步摩擦。

---

## 核心不变量

1. **盘问发送内容，而不是主题**：专门采访用户，了解接收者的角色、专业知识和所需的决策——切勿询问用户只有接收者持有的答案。
2. **差距目标表述**：每个问题都必须瞄准用户所知和利益相关者决定之间的精确界限。
3. **重要性优先排序**：按关键架构影响的降序对问题进行排序，以从部分响应中提取最大价值。
4. **单一想法原子问题**：切勿将多个复合问题组合成一个项目；每个问题都必须有自己的上下文和答案存根。
5. **No Speculative Answer**：不要猜测或捏造利益相关者的业务规则；格式化清晰的提示并附上理由（“为什么这很重要：”）以引出清晰的答案。

## 分步程序 (TWI)

### 第 1 步：明确接收者角色和所需决策
- **行动**：在一次交换中询问用户：(1) 接收者是谁（角色、技术深度）？ (2) 究竟需要解锁哪些决策或事实？
- **要点**：严格关注定义差距，而不是猜测答案。
- **为什么**：校准收件人的观点可确保文档使用适当的语气和技术深度。

### 第 2 步：构建主题问题块
- **操作**：将问题分组到清晰的主题标题（`## <主题>`）下，并按优先级降序对每个主题内的问题进行排序。
- **要点**：对于每个问题，都包含明确的“_为什么这很重要：_”行，解释他们的答案如何影响系统设计。
- **内嵌清单**：
  - [ ] 问题按最重要的顺序排列
  - [ ] 没有复合/嵌套子问题
  - [ ] 每个项目下提供的清晰答案引用块 (`> `)
  - [ ] 包括明确的截止日期和部分答案说明

### 第 3 步：撰写并交付调查问卷文件
- **操作**：将完整的 Markdown 文档写入当前目录下的 `to-questionnaire-<slug>.md` 中。
- **关键点**：以一个包罗万象的“##还有什么？”部分来捕获未知的未知数。
- **为什么**：利益相关者经常拥有标准问题所忽视的背景限制。

## 反合理化护栏

|诱人的合理化|约束规则|工程原理 |
|---|---|---|
| *“我会要求用户猜测利益相关者会喜欢什么。”* | **禁止。将调查问卷瞄准差距。** |猜测利益相关者的偏好会在生产架构中引入错误的假设。 |
| *“将 3 个相关问题合并为一个多部分段落。”* | **执行单一想法原子问题。** |多部分问题让忙碌的利益相关者不堪重负，导致跳过答案。 |
| *“省略‘为什么这很重要’条款以使问题简短。”* | **包含有关答案为何重要的上下文。** |当利益相关者了解工程影响时，他们会给出更好、可行的答案。 |
