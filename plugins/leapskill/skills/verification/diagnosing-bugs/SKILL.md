# 缺陷诊断

一种严格的反馈循环方法，用于诊断和解决疑难 Bug、间歇性问题和性能回归。

## 核心原则

> **在建立可靠地重现红色故障的快速、确定性、自动化反馈循环之前，切勿猜测或假设。**

---

## 核心不变量

1. **理论之前的强制红色循环**：构建快速、自动化的重现命令，并在制定或测试任何假设之前查看它是否失败。
2. **首先进行凭据脱敏**：在显示输出或日志之前使用“<REDACTED>”编辑所有密钥、授权标头、token和机密。
3. **单变量检测**：探测假设边界时一次仅更改一个变量。
4. **唯一的调试标记**：使用唯一的可搜索前缀（例如“[DEBUG-trace]”）标记所有临时诊断日志，以便在提交之前完成清理。
5. **公共接缝回归测试**：在宣布胜利之前，通过在真正的架构接缝处进行永久测试来锁定修复。

---

## 架构和内容地图 (MOC)

```
[ Build Tight Loop ] ──► [ Reproduce & Minimise ] ──► [ 3–5 Ranked Hypotheses ] ──► [ Targeted Probe ] ──► [ Fix & Regression Test ] ──► [ Clean ]
```

|相|核心目标|关键交付成果 |
|---|---|---|
| **阶段 1：构建循环** |构建自动通过/失败信号 |单个可执行命令因该错误而变红 |
| **阶段 2：最小化** |将失败缩小到基本变量 |最小承载重现有效载荷|
| **阶段 3：假设** |制定 3-5 个可证伪的预测 |具有可检验预测的排名假设表 |
| **阶段 4：工具** |用最少的探针测试预测 |标记为“[DEBUG-...]”日志或调试器检查 |
| **阶段 5：修复和测试** |公共接缝处的锁定行为 |永久自动回归测试|
| **阶段 6：清理** |拆除诊断脚手架 |已验证干净的 git 状态并通过测试套件 |

---

## 分步程序 (TWI)

### 第 1 步：构建紧密的反馈循环（第 1 阶段）
- **操作**：构建驱动错误路径的自动化测试运行器（失败测试、CLI 测试夹具、curl 脚本或trace replay）。
- **关键点**：循环必须快速（< 5 秒）、确定性，并断言用户的确切症状。
- **内嵌清单**：
  - [ ] 自动命令存在并已执行
  - [ ] 命令专门针对此错误症状而变为红色
  - [ ] 执行在几秒钟内完成，无需人工干预
- **为什么**：在没有反馈循环的情况下盯着代码会导致猜测和确认偏差。

### 第 2 步：重现并最小化（第 2 阶段）
- **操作**：运行循环以确认复制，然后系统地删除非必要的配置、数据和步骤。
- **关键点**：复制品中剩余的每条线都必须承重（删除它会使环变成绿色）。
- **为什么**：最小重现缩小了假设空间并干净地转换为永久回归测试。

### 第 3 步：提出可证伪的假设（第 3 阶段）
- **行动**：生成 3-5 个排名假设，说明每个假设的明确预测。
- **要点**：使用格式：*“如果X是原因，那么改变Y将使症状消失。”*
- **为什么**：单一假设调试锚定第一印象并浪费时间。

### 步骤 4：插桩与隔离（第 4 阶段）
- **操作**：插入标记探针（`[DEBUG-xxx]`）或检查关键边界处的值。
- **要点**：一次仅更改一个变量；在调整性能错误之前测量基线。
- **为什么**：同时更改多个变量会混淆因果关系。

### 第 5 步：修复、验证和清理（第 5 和第 6 阶段）
- **操作**：编写回归测试，应用最小修复，验证完整套件，并清除所有调试工具。
- **内嵌清单**：
  - [ ] 回归测试在未修复的情况下失败，在修复后通过
  - [ ] 原始未最小化复制品已确认为绿色
  - [ ] 从代码库中清除了所有“[DEBUG-...]”标签
  - [ ] 提交消息中清楚记录了根本原因

## 反合理化护栏

|诱人的合理化|约束规则|工程原理 |
|---|---|---|
| *“我想我看到了代码中的错误，现在让我修复它。”* | **没有自动红色反馈循环就无法进行编辑。** |基于检查修复代码通常可以解决症状，但忽略根本原因。 |
| *“该缺陷是偶发的，因此我们无法自动化测试。”* | **提高再现率（压力、循环、固定时钟）。** | 50% 的偶发率是可调试的；提高再现频率直至可测试。 |
| *“我将在各处添加日志并检查所有输出。”* | **仅限有针对性的标记探针。** |无针对性的伐木会淹没环境并产生清理债务。 |
| *“该修复适用于手动测试，跳过回归测试。”* | **公共接缝处的强制性自动回归测试。** |如果不进行回归测试，该错误将在未来的重构中悄然回归。 |
