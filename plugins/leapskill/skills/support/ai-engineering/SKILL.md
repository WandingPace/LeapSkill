# 人工智能与机器学习工程

通过严格的验证、延迟工程和道德护栏来设计、训练、优化、部署和监控生产机器学习模型和智能体系统。

## 核心原则

> **每个机器学习解决方案都必须超越初始基线，保证训练测试隔离，并满足严格的生产延迟和公平性预算。**

---

## 核心不变量

1. **严格的训练测试隔离**：预处理缩放器、编码器和分词器必须严格适合隔离管道内的训练折叠，以消除数据泄漏。
2. **低于 100 毫秒的推理预算**：同步面向用户的端点必须通过量化 (ONNX/TensorRT/GGUF)、引擎优化或连续批处理实现 $p99 < 80\text{ms}$。
3. **复杂性之前的强制性基线**：在进入深度网络或复杂集成之前，始终以朴素基线（多数类/平均值）和简单线性模型为基准。
4. **人口统计公平性和偏见审核**：每个生产候选者必须通过跨人口统计切片的五分之四差别性影响测试（$\text{ratio} \ge 0.80$）。
5. **连续漂移可观察性**：生产模型必须发出数据漂移指标（KS 测试/群体稳定性指数）和概念漂移警报以触发自动再训练。

## 分步程序 (TWI)

### 第 1 步：要求和数据卫生验证
- **行动**：评估目标指标，评估类别平衡，并建立可重复的验证分割。
- **关键点**：检查时间依赖性。如果数据有时间维度，则采用时间顺序拆分；否则，使用分层 $k$-Fold 交叉验证。
- **为什么**：时间序列数据的随机分割会导致严重的前瞻泄漏和错误的置信度。

### 步骤 2：模型训练和架构选择
- **行动**：拟合朴素基线，进展到梯度增强树或微调神经架构（LLM的 LoRA/PEFT）。
- **关键点**：对于 LLM，将 LoRA 应用于所有注意力和 MLP 投影层，其中 $\alpha = 2 \times r$ 和 4 位 NF4 量化。
- **为什么**：选择性低秩适配以 VRAM 成本的 25% 实现基础模型性能。
- **内嵌清单**：
  - [ ] 建立简单基线（线性/逻辑回归或平均基线）
  - [ ] 跨折叠的交叉验证方差在可接受的范围内 (< 5%)
  - [ ] 检查过拟合诊断（训练损失与验证损失收敛）
  - [ ] 使用贝叶斯优化系统调整超参数

### 步骤 3：偏见、可解释性和稳健性审核
- **行动**：评估子群体之间的公平性并计算 SHAP 特征归因。
- **关键点**：执行五分之四规则（$\text{选择率比率} \ge 0.80$）并计算高风险决策的顶级局部特征属性。
- **为什么**：未被发现的偏见会导致监管违规和未经校准的现实世界歧视。

### 步骤 4：低延迟服务和金丝雀部署
- **操作**：将模型导出到 ONNX 或 vLLM，包装异步 API 服务，并启动 10% 金丝雀部署。
- **关键点**：跟踪整个金丝雀组的 $p99$ 延迟、群体稳定性指数 (PSI) 和错误率。
- **为什么**：金丝雀测试在完全流量暴露之前隔离性能回归。

## 反合理化护栏

|诱人的合理化|约束规则|工程原理 |
|---|---|---|
| *“准确度为 98%，因此我们不需要混淆矩阵。”* | **强制 PR-AUC、F1 和混淆矩阵分析。** |不平衡数据的高精度通常隐藏着退化的多数类分类器。 |
| *“分割前的预处理是无害的。”* | **零数据泄漏：仅限管道式转换器。** |数据集范围内的预处理将测试分布参数泄漏到训练折叠中。 |
| *“模型满足准确性目标，因此跳过偏差检查。”* | **公平审核是强制性的释放门。** |监管和道德标准要求进行人口平等验证。 |
| *“400 毫秒的延迟对于云服务器来说已经足够快了。”* | **交互式端点的 100 毫秒以下 p99 预算。** |微服务之间的高延迟会加剧并降低用户体验。 |
