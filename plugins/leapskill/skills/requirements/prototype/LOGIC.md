# 逻辑原型

一个自包含 HTML 文件（**可分享 demo**），让任何人通过点按钮驱动状态模型。当问题是**业务逻辑、状态迁移或数据形状**时使用：这类东西纸上看着合理，只有推过几个真实 case 才会觉得不对。

因为它是一个文件、零安装，你可以直接交给非开发者（设计师、PM、领域专家），让他们自己感受模型。所以它要说他们的语言，不是说代码的语言。

## 什么时候适合这个形态

- “我不确定这个状态机能不能处理 X 之后 Y 的边界情况。”
- “这个数据模型真的能表达……的情况吗？”
- “我想在写 API 之前先摸一下它应该长什么样。”
- 任何有人想**按按钮、看状态变化**的场景。

如果问题是“界面应该长什么样”，这个分支就不对。用 [UI.md](UI.md)。

## 流程

### 1. 先写清问题

写代码之前，先写下你要原型化的状态模型和问题。一段话，放在 demo 顶部（可见介绍里，不只是注释）。回答错误问题的逻辑原型是纯浪费，所以问题必须显式，之后无论用户在场还是 AFK 回来，都能检查。

### 2. 把逻辑隔离成可移植模块

把真正回答问题的逻辑放进一个 `<script>` block，写成一个小的纯模块，之后可以被整体搬到真实代码库里。页面外壳是丢弃品，这个模块不是。

合适形态取决于问题：

- **纯 reducer**：`(state, action) => state`。action 是离散事件、state 是单个值时合适。
- **状态机**：显式 states 和 transitions。当“当前哪些 action 合法”本身就是问题时合适。
- **一组纯函数**，作用在普通数据类型上。没有隐式当前状态、只有变换时合适。
- **类或模块，方法面清晰**：逻辑确实持有持续内部状态时用。

选最适合问题的形态，而不是最容易接到页面上的形态。保持纯：无 DOM、无 `document`、没有按钮 handler 伸进来。页面调用它；它不反向依赖页面。这是原型能超越自身寿命的关键：问题回答后，验证过的 reducer / machine / 函数集可以独立搬进真实模块。

### 3. 构建可分享 HTML

一个文件，纯 HTML/CSS/JS：无框架、无 bundler、无 server，全部 inline，双击可打开，发邮件也不坏。任何人打开就能跑。

写给非开发者。所有标签都用**领域语言**，不用代码语言：按钮和状态读起来像业务，不像 reducer。用普通话解释正在发生什么。

布局自上而下，层级清晰：

1. **标题和一行说明**：这个 demo 让你探索什么（第 1 步的问题）。
2. **当前状态**：完整相关状态，渲染成可读面板（带标签字段，不是裸 JSON），每次点击后重渲染，让变化可见。有助于非开发者跟上时，突出刚刚变化的部分。
3. **自由探索按钮**：一个 action 一个按钮，始终可用，让任何人按任意顺序戳模型。每次点击 dispatch 对应 action 并重渲染状态。
4. **引导走查**：一组**场景**，一个 tab 一个。每个 tab 有一段普通话场景说明（它设置的情境和要观察什么），下面是按顺序排列的**要按的按钮**。每一步都是真实按钮：点击执行该 action 并进入下一步。开始走查时重置到已知初始状态，保证场景每次运行一致。

选那些纸面上难推理的尴尬场景：happy path、刁钻边界、一次应当非法的尝试。

保持美但克制：干净排版、充足间距、一个强调色。无动画、无噱头：不要让任何东西和状态、按钮抢注意力。

### 4. 交付

把文件发给对方，或替对方打开。他们什么时候点随他们；有价值的时刻是他们说“等等，这不应该可能”或“咦，我以为 X 会不一样”。这些是**想法里的 bug**，正是整个目的。他们想加 action 或场景，就加。原型会演化。

### 5. 捕获答案和原型

原型回答问题后，先捕获答案，再按 [SKILL](SKILL.md) 的方式捕获原型。逻辑原型的特定映射是：验证过的 reducer / machine / 函数集搬进真实模块（决策被吸收）；HTML shell 进 throwaway branch，作为一手来源保留。因为它是自包含单文件，在那里也随时可以重跑。

## 反模式

- **不要加测试。** 需要测试的原型已经不是原型。
- **不要接真实数据库。** 除非问题 specifically 关于持久化，否则用内存状态。
- **不要泛化。** 不要“以后如果要支持 X 怎么办”。原型回答一个问题。
- **不要把逻辑和页面糊在一起。** 纯模块一旦引用 DOM、`document` 或按钮 handler，就不可搬迁。页面必须是纯模块外面的薄壳。
- **不要上框架、bundler 或 server。** 收件人双击一个文件；React app 或 dev server 会毁掉“可分享”。
- **不要把 HTML shell 发进生产。** 页面为手动点击优化，背后那个逻辑模块才值得保留。
