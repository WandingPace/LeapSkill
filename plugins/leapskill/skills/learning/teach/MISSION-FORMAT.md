# MISSION.md 格式

`MISSION.md` 固定放在当前项目的 `Docs/Teach/<topic-slug>/MISSION.md`。它记录用户学习这个主题的**原因**。所有教学决策（下一步教什么、展示哪些资源、设计什么练习）都应能追溯回这份文档。

## 模板

```md
# Mission: {主题}

## Why
{1-3 句。用户追求的具体现实目标。掌握这项技能后，他的生活或工作会发生什么变化？避免“理解 X”这种抽象说法，追问背后的真实成果。}

## Success looks like
- {一个具体、可观察的能力}
- {另一个具体能力}
- {…}

## Constraints
- {时间、预算、已有安排、学习偏好等一切限制条件的边界}

## Out of scope
- {用户明确表示现在不想追的相邻主题，保护最近发展区}
```

## 规则

- **一个主题目录一个 mission。** 如果用户想学两个不相关的东西，就在 `Docs/Teach/` 下建两个主题目录。
- **具体优于抽象。** “十月前跑完半程马拉松”优于“变得更强壮”。“把 Rust CLI 交付给团队”优于“学习 Rust”。
- **对模糊目标要追问。** 用户说不清 why 时，先访谈再动笔。糟糕的 mission 比没有 mission 更糟。
- **现实变化时更新。** Mission 会变。用户目标移动后，更新这个文件，不要让过期 mission 继续引导后续课程。
- **保持短。** 如果 `MISSION.md` 超过一屏，它已经不是指南针，而是变成计划了。
