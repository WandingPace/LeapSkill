# GLOSSARY.md 格式

`GLOSSARY.md` 固定放在当前项目的 `Docs/Teach/<topic-slug>/GLOSSARY.md`，是这个学习主题的权威术语表。所有讲解、练习和学习记录都必须遵循这里的术语。整理它本身就是学习的一部分：能把概念压缩成一句精确定义，说明用户真的理解了。

## 结构

```md
# {主题} Glossary

{一到两句话：这个术语表覆盖什么主题。}

## Terms

**Hypertrophy**:
由反复训练中的机械张力和代谢压力驱动的肌肉增长。
_Avoid_: Bulking, getting big

**Progressive overload**:
通过负荷、容量或强度，系统性地逐步提高对肌肉的要求。
_Avoid_: Pushing harder, levelling up

**RPE (Rate of Perceived Exertion)**:
对一组训练主观困难度的 1-10 自评；10 表示力竭，8 表示大约还能做两次。
_Avoid_: Effort score, intensity rating
```

## 规则

- **只有用户理解了一个术语，才把它加进术语表。** 术语表是压缩后的知识记录，不是用户用来学习的字典。用户刚接触一个概念时，先等他能正确使用，再收录。
- **要有明确取舍。** 同一概念有多个叫法时，选一个最好的，其余作为要避免的别名列出来。语言就是这样被压缩的。
- **定义要短。** 一到两句。定义这个词**是什么**，不是它做什么或怎么做。
- **定义里优先使用术语表已有的词。** 一个术语进入术语表后，后续所有地方都用它，包括其他定义。这样复杂概念之后才更容易理解。
- **出现自然分组时用子标题。** 例如 `## Anatomy`、`## Programming`。术语本来就是一个整体时，平铺列表也可以。
- **显式标记歧义。** 如果一个词在行业里用得很宽泛，在这里写清约定：“在这个工作区里，set 始终指正式组；热身组单独记录。”
- **理解加深后及时修订。** 用户第一周写的定义，到第六周可能是错的。直接原地更新，不要留下过期条目。
