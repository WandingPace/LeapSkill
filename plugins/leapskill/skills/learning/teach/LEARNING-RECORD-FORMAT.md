# 学习记录格式

学习记录固定保存在当前项目的 `Docs/Teach/<topic-slug>/learning-records/` 中，使用顺序编号：`0001-slug.md`、`0002-slug.md` 等。目录按需创建：只在写第一条记录时建立。

它是教学版的 ADR：记录不明显的经验、关键洞察、以及会影响后续课程的既有知识。它还用来计算“最近发展区”。

## 模板

```md
# {学到或确立了什么的短标题}

{1-3 句话：学到了什么（或确立了什么既有知识），以及它为什么影响后续课程。}
```

格式就这么少。学习记录可以只有一段。它的价值在于记录**现在已知这件事**，以及**它为什么改变下一步教什么**，不在于填满章节。

## 可选章节

只有真正有价值时才加。多数记录用不到。

- **Status** frontmatter（`active | superseded by LR-NNNN`）：早期理解被证明有误并被替代时有用。
- **Evidence**（证据）：用户如何证明自己理解了，例如回答了问题、完成了练习、提到了过往经验。这个结论将来可能被重新讨论时值得写。
- **Implications**（影响）：它为后续课程解锁或排除了什么。影响不明显时值得记录。

## 编号

扫描 `Docs/Teach/<topic-slug>/learning-records/` 中现有编号的最大值，然后加一。

## 什么时候写学习记录

满足任一条件就写：

1. **用户真的理解了某个不简单的概念。** 不只是“接触过”，而是有证据能正确使用。这会抬高下一步教学的下限。
2. **用户透露了既有知识。** “我已经会 X 了。”记录下来，后续课程不要重教。同时记录他声称的掌握深度。
3. **纠正了一个误解。** 用户之前理解错了，现在知道为什么。这类记录价值很高：它们能预测相关主题之后会在哪里卡住。
4. **学习目标因新理解而改变。** 用户发现自己真正关心的东西和原来以为的不一样。交叉链接 [[MISSION.md]] 并更新它。

### 不适合记录的内容

- 只是课上覆盖过的材料。覆盖不等于学会，等有证据再记。
- [[GLOSSARY.md]] 已经用术语定义简洁记录过的内容。不要重复。
- 逐次课程的活动日志。学习记录不是日记，而是能影响教学决策的洞察。

## 被替代

当后面的记录推翻了前面的（理解加深或被纠正），不要删除旧记录，而是标记 `Status: superseded by LR-NNNN`。理解如何演进，本身就是有用信号。
