# Skill 专属机制

这是 [`writing-for-agents`](SKILL.md) 的 Skill 专属分支：当你要写的文档本身就是一个 skill 时，需要额外关注 frontmatter、调用方式和路由 skill 的设计。其余写作原则仍然以 [`SKILL.md`](SKILL.md) 中的通用参考为准。

## 调用方式

有两种选择，本质是在两种成本之间做取舍：

- **模型自动调用**：保留 `description`，因此智能体可以自己判断并调用这个 skill，其他 skill 也可以引用它。你仍然可以手动输入名称调用；模型自动调用能力不会限制人工调用。`description` 是 skill 的顶层上下文指针，会一直留在上下文里。代价是常驻的上下文成本，收益是可发现性。如果这个 skill 的内容全是参考资料，它还可以作为共享参考的存放处：其他 skill 可以引用它，多个 skill 都需要的规则就能集中维护。做法：不要设置 `disable-model-invocation`，并写一个面向模型的 `description`，明确列出触发条件。[`SKILL.md`](SKILL.md) 中的指针写法规则同样适用。
- **仅用户手动调用**：去掉模型对 `description` 的感知，只有人输入名称才能调用，其他 skill 也不能引用它。上下文成本为零，但会增加人的记忆成本：你必须自己记得这个 skill 存在。做法：设置 `disable-model-invocation: true`；此时 `description` 面向人，只保留一句话摘要，不写触发列表。

只有当智能体必须能独立调用这个 skill，或其他 skill 必须引用它时，才选择模型自动调用。如果它只会被人手动调用，就做成仅用户手动调用，省下常驻上下文的成本。

两个仅用户手动调用的 skill 都需要的共享内容，不能放在其中任何一个里面：因为没有 `description`，它们互相都无法引用。应把这类内容放到 skill 系统之外的普通文件里，作为外部参考资料，让任何 skill 都能通过路径指向它。

## 按调用方式拆分

拆分 skill 时有两类依据：按步骤拆分的规则见 [`SKILL.md`](SKILL.md)；按调用方式拆分时，只有两种情况值得拆出一个模型自动调用的 skill：一是它有一个真正会出现在你提示词里的独立触发词，二是其他 skill 必须能引用它。新增一个模型自动调用的 skill，就要新增一条常驻的 `description`，因此这种独立可调用性必须值得付出这个成本。

## 路由 skill

当仅用户手动调用的 skill 多到你记不住时，可以用一个**路由 skill** 解决：它也是一个仅用户手动调用的 skill，内容是列出其他 skill 的名称和适用场景。这样你只需要记住一个入口，而不是记住所有 skill。路由 skill 只能提示你该用哪个 skill，不能自动调用它们：仅用户手动调用的 skill 没有 `description`，所以只有人能触发。
