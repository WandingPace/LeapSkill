# XLua 热修复

先读取目标 C# 声明、实现和直接相关调用，确认完整类型名、静态/实例方法、参数顺序与类型、`ref/out`、默认参数、返回值、重载、基类调用和实际副作用。存在多个候选或找不到真实定义时先报告缺口，不从目录或文件名猜 `CS.*` 路径。

用户以修订号、提交或“最近一次 C# 提交”指定来源时，按项目 VCS 规则锁定准确修订号和作者；SVN 项目同时读取该修订号的 `svn diff` 与 `svn cat` 完整文件，只把真实变更映射到完整方法体。不得用当前工作树替代提交快照，也不得在“当前用户最近提交”无匹配时静默改用其他作者。

再在项目声明的 Hotfix 根或目标附近查活跃先例，确认注册 API、`self`、原实现/基类调用、私有访问、转型、构造函数、Lua 版本和条件加载方式。需要保留原逻辑并在前后追加、短路或修正结果时优先采用项目已证明可回调原方法的 `hotfix_ex`；原逻辑必须完整替换时使用 `xlua.hotfix`。历史归档或注释只能当线索；同一 `<完整类型, 方法>` 不保留多个顺序相关的注册。

只转换用户要求的行为，保持参数、返回路径、早退和副作用顺序。替换后再调用同名方法可能递归；C# 集合保持 `Count` 和从 0 开始的下标，Lua 表才使用 `#` 和从 1 开始的下标；Unity 假空值不等于 Lua `nil`；补丁状态和辅助函数默认使用 `local`，同一目标只保留一个最终注册。重载、泛型、`ref/out`、构造函数、私有访问和运行时转型没有同版本先例时保留未决。

Lua 数值进入 C# 参数、字段或属性时，读取 [XLua 数值互操作](references/xlua/numeric-interop.md)，按接收端真实类型决定是否使用 `CS.XLua.Cast.*`；不能只根据 Lua 值或事件号猜装箱类型。目标是 CODM Client 时读取 [CODM Hotfix 执行与验收](references/xlua/codm-hotfix-execution.md)，按目标包版本、加载入口和授权决定写入、注入与验证层级。

用户已要求落实 Hotfix 时，从当前请求、已有上下文、项目规则或已核实的唯一活跃加载入口确定目标文件后可以写入，不要求用户逐字指定路径。存在多个会改变加载行为的候选且无法自行消歧时，说明差异并询问必要信息，继续完成不依赖该选择的代码与静态核对；写入目标确定前只提供草案。项目没有声明模板、输出位置或加载入口时不从别的项目复制路径；仅生成或审查代码的请求不因找到入口而扩大为项目写入。

静态核对目标类型或方法、全部参数、注册 API、集合下标、空值、枚举、位运算、私有访问和新增全局符号。项目提供且当前任务需要时，再运行能够覆盖改动的最小 Lua 解析、代码检查、沙箱或加载检查。

返回目标证据、Hotfix 产物或草案、关键语义映射、已执行验证和未决边界；提交来源任务同时报告修订号、作者、变更 C# 文件数和转换方法数。C# 编译、Lua 语法、脚本加载、Hotfix 命中、Editor 功能和真机结果是不同证据，分别报告。
