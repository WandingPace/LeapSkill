# 阶段边界

**阶段（phase）** 是一个会话内的一块工作：拷问、实现、QA。定义刻意保持模糊：当你觉得“这部分差不多了”，阶段就结束了。

**阶段边界** 是两个阶段之间的缝隙，也是唯一应该做这类决策的地方。阶段中间没有决策可做：要么继续，要么把剩余工作拆给子代理。在阶段中间压缩上下文，会让 agent 丢掉工作主线。

## 五个选项

| 选项 | 作用 |
| --- | --- |
| **Continue** | 留在当前会话，完全不切换上下文 |
| **`/clear`** | 清空上下文窗口，从零开始 |
| **`/handoff`** | 写一份可移植 Markdown 文件，用它在新会话恢复工作 |
| **Subagent** | 把任务发到独立上下文窗口，拿回报告 |
| **`/compact`** | 压缩当前上下文，用摘要开启新会话 |

## 决策树

在阶段边界处从上往下判断，第一个“是”生效。

**1. 能在当前会话继续吗？** 两种情况算“能”：下一阶段需要把这一阶段当作**一手来源**，或者剩余 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k token）足够容纳下一阶段。拷问 → 实现是标准的“能”：实现阶段需要完整推理过程，不是它的摘要。Continue 没有成本也不丢信息，所以先排除它。

**2. 当前上下文和接下来的工作无关吗？** 这个会话里的所有东西（探索、决策、死胡同）都可以丢掉吗？可以就用 **`/clear`**。它是最便宜的一步：不花时间，还回整个窗口。`/clear` 也不是终点，旧会话仍然可以恢复。

判断错的代价是单向的。清掉一个**相关**上下文，你会丢掉构建背后的**为什么**，之后无论读多少遍 diff 都补不回来。

**3. 需要交接吗？** `/handoff` 的适用面很窄。只有这些情况需要：

- 切换到**新 harness**（Claude → Codex）
- 移到**新目录**或新仓库
- 把工作交给**同事**
- 在阶段中间发现一个支线任务，想分出去做，又不打断当前工作

这份列表就是完整条件。`/handoff` 买到的是**可移植性**：一份能被带走的文件。没有东西要带走，就不需要它。

**4. 任务可以无人值守完成吗？** 它的范围足够小，可以离开键盘运行、不需要你不断纠偏吗？可以就发给**子代理**，当前会话保持不动。自动 review 是标准场景：agent 读 diff、写报告，期间不需要你。

**5. 否则用 `/compact`。** 上下文相关、同一个 harness、同一个目录，而且你还要继续参与：决策树通常落在这里，而且经常落在这里。给它一句指令（`/compact 接下来要做 QA`），让摘要保留下一阶段需要的内容。

`/compact` 是**默认兜底，不是第一选择**。它放在最后，是因为前四个问题都更便宜或更精确。人们一上来就 compact 的典型失败是：新会话对某个被摘要压扁的决策表现出自信但错误的理解。

## 一手来源与二手来源

除了 **Continue**，其他每个动作都会把**一手来源**变成**二手来源**：真实发生的会话被它的摘要替代。取舍形状始终相同：

| 来源 | 信息 | 噪音 | 调整空间 |
| --- | --- | --- | --- |
| 一手（Continue） | 完整 | 多 | 少 |
| 二手（`/compact`、`/handoff`） | 有损 | 少 | 多 |

这也是问题 1 排在最前面的原因。只有当继续留下的成本超过它省下的损失时，才值得承担有损压缩。

## 这些是判断题

这些问题没有客观答案：每个都包含品味，同一个边界在不同日子也可能走向两条路。价值在于**按顺序**问，并且只在边界处问，而不是工作做到一半问。
