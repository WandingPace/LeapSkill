# 代码库设计

设计深度、高杠杆率的模块，将复杂的域行为封装在放置在清晰的架构接缝处的最小接口后面。

---

## 核心不变量

1. **深度除以表面积**：最大化内部实现杠杆，同时最小化接口表面积（方法很少，原始参数简单）。
2. **作为测试表面的接口**：外部调用者和单元测试跨越完全相同的接缝；切勿刺穿接口来测试内部私人管道。
3. **删除测试**：如果删除模块导致复杂性消失，则这是不必要的传递；如果复杂性分散在 $N$ 调用者中，那么它就值得了。
4. **真实接缝与假设接缝**：一个适配器表示假设接缝；仅当至少有两个具体适配器在其上变化时才引入接口接缝。
5. **精确设计词汇**：严格使用规范术语（**模块**、**接口**、**深度**、**接缝**、**适配器**、**杠杆**、**局部性**）；避免模​​糊的同义词（服务、组件、边界）。

## 分步程序 (TWI)

### 第 1 步：评估当前界面深度和接缝
- **操作**：检查模块的公共方法、参数签名和调用站点。
- **要点**：检查界面认知开销与内部能力的比率。
- **为什么**：浅层模块迫使调用者了解内部机制，破坏局部性。

### 步骤 2：应用删除测试并简化签名
- **行动**：将细粒度的程序方法整合为统一的、揭示意图的操作。
- **关键点**：隐藏接缝后面的内部状态转换和依赖实例化。
- **内嵌清单**：
  - [ ] 方法减少到最少的基本操作
  - [ ] 依赖项是传入的而不是内部创建的
  - [ ] 函数返回值而不是改变全局副作用

### 步骤 3：将接缝与单元测试线束对齐
- **操作**：构建测试套件以严格通过其公共接口来运行模块。
- **要点**：消除私有辅助函数的内部模拟和测试。
- **为什么**：通过接口进行测试可确保测试在内部重构中幸存下来而不会损坏。

### 步骤 4：探索替代方案（设计两次）
- **行动**：在设计复杂或基础模块时，在编码之前起草 2-3 个完全不同的界面设计。
- **关键点**：比较候选人的深度、位置和呼叫者人体工程学。
- **为什么**：首先想到的界面很少是最深入或最可维护的。

## 反合理化护栏

|诱人的合理化|约束规则|工程原理 |
|---|---|---|
| *“公开私有辅助函数，以便我们可以为它们编写单元测试。”* | **禁止。仅通过公共接口进行测试。** |测试私有助手将测试与实现细节结合起来并防止重构。 |
| *“为单个实现创建接口和适配器。”* | **在提取通用接缝之前等待 2 个适配器。** |推测性概括会产生浅薄的、不必要的抽象层。 |
| *“将这个 100 行内聚函数分解为 5 个一次性文件。”* | **维护深层模块内的局部性。** |过度的碎片化会增加认知负荷并分散相关逻辑。 |
