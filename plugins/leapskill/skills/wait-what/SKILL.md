# 等等什么

重置对话假设，去掉复杂的行话，并使用基于规范领域术语 (`CONTEXT.md`) 的 ASD-STE100 简化技术英语重新解释技术提案。

---

## 核心不变量

1. **简化技术英语（STE）**：使用清晰、无歧义的句子；将词汇限制为具体的、可观察的概念，而不会造成认知超载。
2. **领域词汇保真度**：严格使用`CONTEXT.md`（或`CONTEXT-MAP.md`）中建立的规范名词；避免使用口语同义词。
3. **重置基本假设**：从复杂的实现细节中退一步，将解释重新锚定在核心用户问题和高层架构中。
4. **具体对比（之前与之后）**：使用简单的并排示例或 ASCII 图表来直观地演示变化。
5. **检查理解**：以一个直接问题作为结论，确认新的解释是否清晰。

## 分步程序 (TWI)

### 第 1 步：去除行话并重置上下文
- **行动**：承认歧义，放弃低级实施细节，并用简单的英语陈述主要目标。
- **要点**：检查 `CONTEXT.md` 以确保使用正确的域术语，而无需发明新术语。
- **为什么**：当解释同时引入多种相互竞争的心理模型时，就会发生认知疲劳。

### 第 2 步：制定简化的解释
- **行动**：以简短、结构化的要点进行重新推介：
1.当前的问题是什么？
2. 拟议的变更是什么？
3. 为什么这样可以干净利落地解决问题？
- **内嵌清单**：
  - [ ] 句子平均少于 15 个字
  - [ ] 使用的规范领域词汇
  - [ ] 抽象隐喻被具体力学取代

### 第 3 步：保持核心理解一致
- **行动**：在继续之前提出一个有针对性的问题来验证理解情况。
- **为什么**：防止继续走错位的技术道路。

## 反合理化护栏

|诱人的合理化|约束规则|工程原理 |
|---|---|---|
| *“大声或用更多的话重复之前的解释。”* | **从一个全新的、更简单的基线角度重新倾斜。** |重复同样的解释并不能解决根本的认知混乱。 |
| *“使用复杂的行业类比和隐喻。”* | **使用具体、直接的技术英语 (STE)。** |类比引入了漏洞抽象并隐藏了技术现实。 |
| *“假设用户理解并开始修改文件。”* | **行动前确认与明确的问题一致。** |在没有相互明确的情况下继续进行会导致工作被拒绝和 PR 被恢复。 |
