# 为代理商写作

编写和完善代理使用的文档：技能、“AGENTS.md”/“CLAUDE.md”或通过上下文指针访问的文档。包装不同；写作原则则不然。

---

## 核心不变量

1. **10 项创作原则**：严格遵守飞行前检查、描述中的零流程、MOC 架构（< 500 行）、TWI 清晰度、内联检查表、每个概念一个术语、零硬编码秘密以及将形式与失败匹配。
2. **上下文负载与认知负载**：内联每个分支需要的内容；将只有某些分支才能到达的上下文指针推到后面。
3. **前置引导词**：用精确的标记（*紧*、*红色*、*示踪子弹*）来招募模型先验，而不是冗长的重新解释。
4. **可观察的完成标准**：每一步都必须以可检查的、详尽的完成界限结束，以防止过早宣布胜利。
5. **描述中的零流程**：描述定义触发边界（“在...时使用”、“不要用于...”），绝不是工作流配方。

```
[ Context Pointer / Description ] ──► [ SKILL.md: Map of Content ] ──► [ Disclosed References / Scripts ]
```

|域名 |关键机制|参考|

## 信息层次结构

文档是根据**步骤**（有序操作）和**参考**（定义和规则）构建的：

1. **文件内步骤**：主要层 - 代理按顺序执行的操作。
2. **文件内参考**：按需查阅；短表或清单与步骤位于同一位置。
3. **公开的引用**：推入由指针到达的单独文件中，仅在该分支触发时加载。

---

## 分步程序 (TWI)

### 第 1 步：设计上下文指针和触发边界
- **操作**：使用前置引导词、不同的触发分支和明确的否定排除来起草指针。
- **要点**：切勿将工作流程步骤放在指针或说明内。
- **为什么**：当流程步骤出现在描述中时，模型会遵循这些步骤并跳过详细的正文。

### 步骤 2：将正文构建为内容图
- **操作**：将主 Markdown 文件组织为具有简洁标题、TWI 步骤和内联检查表的执行地图。
- **要点**：将主文件控制在 500 行以内；将深层模式公开到参考文件中。
- **为什么**：注意力在过长的文档中变得稀疏，导致指令被跳过。

### 步骤 3：定义可检查的完成界限
- **行动**：以明确的完成标准结束每个程序。
- **内嵌清单**：
  - [ ] Frontmatter 名称为 kebab-case 并匹配文件夹
  - [ ] 描述具有积极的触发因素和消极的排除（“请勿用于...”）
  - [ ] 主要文档少于 500 行
  - [ ] 没有硬编码的秘密、API 令牌或用户主路径
- **为什么**：明确的界限可以防止步骤过早终止和未经验证的假设。

## 反合理化护栏

|诱人的合理化|约束规则|工程原理 |
|---|---|---|
| *“我将在描述中列出步骤，以便更好地触发。”* | **禁止：描述定义触发器，而不是步骤。** |模型执行摘要描述并跳过详细的主体指令。 |
| *“更多文档总是更好。”* | **积极修剪：无情地消除空操作。** |过多的线条会分散注意力并增加认知和情境负荷。 |
| *“我可以使用全部大写的‘必须’，而不是解释原因。”* | **解释推理（TWI：行动、要点、原因）。** |解释为什么会产生稳健的概括；严格的禁令会导致迅速注射。 |
| *“为了方便起见，将所有内容保存在一个文件中。”* | **渐进披露：披露大量引用。** |单文件蔓延会降低上下文效率和任务焦点。 |
